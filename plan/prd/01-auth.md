# PRD-01: 인증 / 권한

| 항목 | 값 |
|---|---|
| 상태 | **Confirmed** (2026-09-23) |
| 최종 수정 | 2026-09-23 |
| 선행 문서 | PRD-02 (시크릿·해싱·개인정보) |

## 1. 목적 / 배경

서비스는 기본적으로 공개 큐레이션 사이트이나, 개인화 기능과 운영 관리를 위해
**일반 회원과 관리자** 2개 역할을 둔다 (2026-09-23 확정).

## 2. 역할 정의

| 역할 | 로그인 | 주요 권한 |
|---|---|---|
| 비로그인 방문자 | 불필요 | 메인 열람, 검색, 논문 상세 열람, 원문 이동 |
| 일반 회원 | 필요 | 위 + **관심 키워드 구독 피드** (3절) |
| 관리자 | 필요 | 위 + 수집 키워드·소스 관리, 배치 모니터링, 콘텐츠 관리 |

## 3. 일반 회원 기능 — 관심 키워드 구독 (2026-09-23 확정)

일반 회원에게 제공하는 기능은 **관심 키워드 구독**으로 확정한다.
C-9(PRD-03 §2가 "PRD-01 확정 후 별도 검토"로 미뤄둔 항목)가 이것으로 해소된다.

### 3.1 동작 범위 — 수집이 아니라 필터 (중요)

구독 키워드는 **수집 질의어를 확장하지 않는다.** 수집 배치는 기본 4키워드
(보안 / 해킹 / 사이버 / AI)로 고정되며, 회원의 구독 키워드는 **이미 수집·번역되어
DB에 저장된 항목을 거르는 저장된 질의(saved query)** 로만 동작한다.

```
수집 배치 : 보안 / 해킹 / 사이버 / AI  (고정)
              ↓
          DB (번역 완료)
              ↓
 회원 A 피드 : ['랜섬웨어', 'LLM'] 로 필터
 회원 B 피드 : ['공급망'] 로 필터
```

**이 선택의 이유** — 구독 키워드가 수집 질의어까지 확장되면 수집량과 GPU 번역 부하가
`f(회원 수)`가 되어 PRD-03 FR-27의 수집 상한과 R-1(GPU 부하) 계산이 무의미해진다.
필터 방식은 부하가 회원 수와 무관하게 고정된다.

**이 선택의 한계** — 기본 4키워드로 수집되지 않은 주제는 애초에 DB에 없으므로,
회원이 그 키워드를 구독해도 결과가 영영 비어 있다. UI에서 이를 알려야 한다(FR-9).

### 3.2 검색 기능과의 관계

구독 키워드 필터는 PRD-05의 검색과 **동일한 색인·동일한 질의 경로**를 쓴다.
별도 매칭 엔진을 만들지 않는다. 구독은 "자주 쓰는 검색어를 저장해 둔 것"에 가깝다.

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 일반 회원과 관리자 2개 역할을 지원한다 | Must |
| FR-2 | 비로그인 상태에서도 메인 페이지 열람, 검색, 논문 상세 열람, 원문 이동이 가능하다 | Must |
| FR-3 | 관리자만 수집 키워드(PRD-03 FR-2)와 소스 목록을 변경할 수 있다 | Must |
| FR-4 | 관리자만 배치 실행 현황과 실패 로그를 조회할 수 있다 | Must |
| FR-5 | 권한 검사는 프론트엔드 표시 제어가 아닌 서버 측에서 강제한다 | Must |
| FR-6 | 일반 회원은 관심 키워드를 등록·수정·삭제할 수 있다 | Must |
| FR-7 | 등록한 키워드로 구성된 개인 피드를 조회할 수 있다 | Must |
| FR-8 | 구독 키워드는 수집 질의어에 영향을 주지 않는다 (3.1) | Must |
| FR-9 | 구독 키워드의 결과가 0건이면 "기본 수집 범위(보안/해킹/사이버/AI) 밖일 수 있다"는 안내를 노출한다 | Should |
| FR-10 | 회원당 구독 키워드 개수 상한을 둔다 | Should |

## 5. 인증 방식 — 확정 (2026-09-23)

| 항목 | 결정 | 근거 |
|---|---|---|
| 가입 방식 | **이메일 + 비밀번호** | 온프레미스 배포에서 소셜 로그인은 외부 IdP 의존을 만든다. 폐쇄망에 가까운 환경(PRD-02 §8)과 맞지 않는다 |
| 가입 개방 | **공개 가입** (초대제 아님) | 공개 큐레이션 사이트의 성격상 초대제는 회원 기능을 사실상 죽인다 |
| 이메일 인증 | **하지 않는다** | 메일 발송 인프라를 온프레미스에 두는 비용이 이득보다 크다. 이메일은 식별자일 뿐 연락 수단이 아니다 |
| 세션 | **JWT 액세스(30분) + 리프레시 토큰(14일)** | 리프레시는 `httpOnly`·`Secure`·`SameSite=Lax` 쿠키 |
| 비밀번호 해싱 | **Argon2id** | PRD-02 FR-9 |
| 관리자 계정 | 환경 시드 + **최초 로그인 시 변경 강제** | PRD-02 FR-12 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-11 | 이메일+비밀번호로 가입·로그인한다. 소셜 로그인을 두지 않는다 | Must |
| FR-12 | 액세스 토큰은 30분, 리프레시 토큰은 14일 만료 | Must |
| FR-13 | 리프레시 토큰은 `httpOnly` 쿠키로만 전달하고 로컬 스토리지에 두지 않는다 | Must |
| FR-14 | 로그아웃 시 리프레시 토큰을 서버에서 무효화한다 | Must |
| FR-15 | 회원당 구독 키워드 상한은 **20개** | Must |
| FR-16 | 탈퇴 시 회원 행과 구독 키워드를 즉시 삭제한다 (PRD-02 FR-21) | Must |

## 6. 데이터 모델

| 테이블 | 필드 | 비고 |
|---|---|---|
| `users` | `id`, `email`(unique), `passwordHash`, `role`, `mustChangePassword`, `createdAt` | `role` = `member` \| `admin` |
| `user_keywords` | `id`, `userId`, `keyword`, `createdAt` | 회원당 20개 상한 (FR-15) |
| `refresh_tokens` | `id`, `userId`, `tokenHash`, `expiresAt`, `revokedAt` | 무효화용 (FR-14) |

> 개인정보는 이메일 하나뿐이다 (PRD-02 §7).

## 7. API 명세

| Method | Path | 설명 | 인증 |
|---|---|---|---|
| POST | `/api/auth/signup` | 가입 | 불필요 |
| POST | `/api/auth/login` | 로그인 — 액세스 토큰 + 리프레시 쿠키 | 불필요 |
| POST | `/api/auth/refresh` | 액세스 토큰 재발급 | 리프레시 쿠키 |
| POST | `/api/auth/logout` | 리프레시 토큰 무효화 | 회원 |
| POST | `/api/auth/password` | 비밀번호 변경 | 회원 |
| DELETE | `/api/auth/me` | 탈퇴 | 회원 |
| GET·PUT | `/api/me/keywords` | 구독 키워드 조회·갱신 | 회원 |
| GET | `/api/me/feed` | 구독 키워드 기반 피드 (PRD-05 질의 경로 재사용) | 회원 |
| GET·PUT | `/api/admin/sources` | 수집 소스·키워드 관리 (FR-3) | 관리자 |
| GET | `/api/admin/batches` | 배치 실행 현황·실패 로그 (FR-4) | 관리자 |

## 8. 수용 기준

- [ ] 로그인 없이 메인·검색·논문 상세가 모두 보인다
- [ ] 가입 후 관심 키워드를 20개까지 등록할 수 있고 21개째는 거부된다
- [ ] 구독 키워드 피드가 검색과 같은 결과 규칙으로 나온다
- [ ] 일반 회원이 `/api/admin/*`를 호출하면 서버가 403으로 막는다 (FR-5)
- [ ] 관리자 초기 비밀번호로 로그인하면 변경 화면으로 강제 이동한다
- [ ] 로그아웃 후 이전 리프레시 쿠키로 재발급이 되지 않는다

## 9. 미결 사항

없음 (2026-09-23 전부 확정).

**의도적으로 하지 않기로 한 것** — 소셜 로그인, 이메일 인증, 비밀번호 찾기 메일 발송.
비밀번호를 잊으면 관리자가 재설정한다. 메일 인프라가 없기 때문이며,
나중에 SMTP를 붙이면 그때 이 문서를 고친다.

## 10. 개인 피드 진입점

GNB 계정 메뉴 안의 "내 피드" (PRD-04 §3). 별도 페이지 `/feed`이며
**레이아웃은 PRD-06의 목록 페이지를 재사용한다** (PRD-06 §9 해소).
