# PRD-06: 검색 결과 · 카테고리 목록 페이지

| 항목 | 값 |
|---|---|
| 상태 | **Confirmed** (2026-09-23 신설·확정) |
| 최종 수정 | 2026-09-23 |
| 선행 문서 | PRD-04 (카드 컴포넌트·톤), PRD-05 (질의·결과 데이터) |

## 1. 목적 / 배경

PRD-04는 메인 페이지만 책임지고 "검색 결과 페이지"와 "카테고리 목록 페이지"를
Non-goal로 두었다. 그런데 PRD-04 FR-1(GNB 검색창)·FR-6(Hero 검색 바)·FR-16(더보기)과
PRD-05 FR-15(결과 페이지 이동)가 모두 Must였다. **검색창은 있는데 결과 화면이 없고,
더보기 버튼은 갈 곳이 없는 상태**였다 (C-3).

이 문서가 그 목적지를 정의한다.

## 2. 범위

**포함:**
- 검색 결과 페이지 (`/search`)
- 카테고리 목록 페이지 (`/news/international`, `/news/domestic`, `/papers`)
- 두 페이지가 공유하는 목록 레이아웃·필터 바·페이지네이션
- 결과 없음 / 로딩 / 오류 상태

**제외 (Non-goals):**
- 질의 파싱·색인·랭킹 로직 → PRD-05
- 카드 컴포넌트 자체의 디자인 → PRD-04 §4.1·§4.2를 **그대로 재사용**한다
- 논문 상세 페이지 → PRD-04 §10
- 회원 개인 피드 화면 → PRD-01 §3 (레이아웃은 이 문서를 재사용할 수 있다)

## 3. 사용자 / 역할

PRD-01 §2와 동일. **두 페이지 모두 비로그인 방문자가 제한 없이 이용한다**
(PRD-01 FR-2, PRD-05 FR-10).

## 7. API 명세

**엔드포인트는 하나다.** 검색·카테고리 목록·내 피드가 전부
`GET /api/contents`의 파라미터 차이일 뿐이다. 전체 계약은 `../architecture.md` §9.

| 화면 | 호출 |
|---|---|
| 검색 결과 | `/api/contents?q=…&type=…&kw=…&sort=…&page=…` |
| 국제 뉴스 목록 | `/api/contents?category=international&sort=recent&page=…` |
| 국내 뉴스 목록 | `/api/contents?category=domestic&sort=recent&page=…` |
| 논문 목록 | `/api/contents?type=paper&sort=recent&page=…` |
| 내 피드 | `/api/me/feed?page=…` (내부적으로 동일 질의) |

응답이 같은 스키마이므로 **목록 컴포넌트 하나를 5개 화면이 공유한다.**

## 8. 수용 기준 (Acceptance Criteria)

- [ ] GNB 검색창에 입력하고 실행하면 `/search`로 이동해 결과가 보인다
- [ ] Hero 검색 바에서 실행해도 같은 화면·같은 결과가 나온다
- [ ] 결과 헤더에 질의어, 건수, 검색 범위가 함께 보인다
- [ ] 뉴스만 / 논문만으로 걸러낼 수 있고, 그 상태가 URL에 남는다
- [ ] 필터를 건 URL을 새 탭에 붙여넣으면 같은 화면이 재현된다
- [ ] 메인의 "더보기"를 누르면 해당 카테고리 목록 페이지로 간다
- [ ] 결과가 0건일 때 "왜 안 나오는지"(검색 범위)를 알 수 있다
- [ ] 목록 페이지에는 3D Hero가 없다

## 9. 확정 사항 (2026-09-23)

### 9.1 페이지네이션 — 페이지 번호

**무한 스크롤을 쓰지 않는다.** FR-6이 "필터·정렬 상태를 URL에 반영해 공유·새로고침에도
유지"를 Must로 요구하는데, 무한 스크롤은 스크롤 위치를 URL에 담지 못한다.

| 항목 | 값 |
|---|---|
| 방식 | 페이지 번호 (`?page=2`) |
| 페이지당 건수 | **20건** |
| 컨트롤 | 이전 / 페이지 번호 / 다음. 총 건수 표기 |

### 9.2 목록 레이아웃 — 타입별로 다르게

| 타입 | 레이아웃 |
|---|---|
| 뉴스 | 메인과 동일한 **카드 그리드** (썸네일이 있어 그리드가 살아난다) |
| 논문 | **리스트형** — 1열 전폭, PRD-04 §4.2의 텍스트 카드를 가로로 늘린 형태 |
| 검색 결과 (혼합) | **리스트형 통일** — 뉴스·논문이 섞이면 그리드에서 높이가 어긋난다. 뉴스는 좌측에 작은 썸네일(80×80) |

### 9.3 `matchedKeywords[]` 필터 — 노출한다

PRD-05 §5 해석 A를 **UI로 노출하기로 확정한다** (FR-11a 해소).

| 항목 | 값 |
|---|---|
| 형태 | 필터 칩 — `보안` `해킹` `사이버` `AI` |
| 위치 | 타입 필터(뉴스/논문) 바로 아래, 같은 필터 바 |
| 동작 | 다중 선택(OR). URL 파라미터 `?kw=보안,AI` |
| 카테고리 필터와의 관계 | 독립 축이다 (PRD-03 §9.1). 동시 적용되면 AND |

### 9.4 URL 형태

| 경로 | 화면 |
|---|---|
| `/search?q=…&type=…&kw=…&sort=…&page=…` | 검색 결과 |
| `/news/international` | 국제 뉴스 목록 |
| `/news/domestic` | 국내 뉴스 목록 |
| `/papers` | 논문 목록 |
| `/feed` | 회원 개인 피드 (PRD-01 §10) |

목록 경로는 쿼리스트링(`/list?category=…`)이 아니라 **경로 분리**로 간다.
사람이 읽을 수 있고, 카테고리가 3종 고정(PRD-03 §9.1)이라 경로가 늘지 않는다.

### 9.5 개인 피드는 이 레이아웃을 재사용한다

PRD-01 FR-7의 `/feed`는 **§9.2의 검색 결과 리스트형을 그대로 쓴다.**
질의어 대신 회원의 구독 키워드가 들어갈 뿐이다(PRD-01 §3.2).

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-17 | `/feed`는 검색 결과 페이지 컴포넌트를 재사용하고, 헤더 문구와 0건 안내만 다르게 한다 | Must |

### 9.6 자동완성

PRD-05 §10.4에서 1차 미지원으로 확정. 검색창에 자동완성 UI를 두지 않는다.
