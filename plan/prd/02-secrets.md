# PRD-02: 보안 시크릿 · 개인정보 관리 정책

| 항목 | 값 |
|---|---|
| 상태 | **Confirmed** (2026-09-23) |
| 최종 수정 | 2026-09-23 |
| 선행 문서 | PRD-01 (인증), architecture.md (배포 형태) |

## 1. 목적 / 배경

Docker Compose 온프레미스 단일 서버 구성에서, **어떤 비밀값을 어디에 두고
어떻게 주입하며 무엇을 저장소에 커밋하지 않을지**를 정한다.
클라우드 시크릿 관리 서비스를 전제할 수 없다(`architecture.md` §1).

## 2. 범위

**포함:** 시크릿 저장·주입 방식, `.gitignore` 기준, 비밀번호·토큰 정책,
로그 마스킹, 개인정보 보관·파기, 허용 아웃바운드 목록

**제외:** 네트워크 방화벽 구성, OS 계정 관리, 물리 보안

## 3. 시크릿 저장 방식 — 확정

**Docker Compose 파일 기반 `secrets` + 비민감 설정은 `.env`.**

```
mypage/
├── .env                 # 비민감 설정만 (포트, 배치 시각, 수집 상한 등). 커밋 O
├── .env.example         # 템플릿. 커밋 O
├── secrets/             # 민감값. 파일 1개당 값 1개. 커밋 X
│   ├── db_password
│   ├── jwt_secret
│   ├── naver_client_secret
│   ├── smtp_password
│   └── admin_initial_password
└── docker-compose.yml   # secrets: 블록으로 컨테이너에 파일 마운트
```

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-1 | 민감값은 `secrets/` 아래 파일로 두고 Compose `secrets:`로 마운트한다 | Must |
| FR-2 | 민감값을 **환경변수로 주입하지 않는다** — `docker inspect`·`/proc/*/environ`에 노출된다 | Must |
| FR-3 | 애플리케이션은 `*_FILE` 관례로 경로를 받아 파일에서 읽는다 (예: `DB_PASSWORD_FILE`) | Must |
| FR-4 | `secrets/` 파일 권한은 `0600`, 소유자는 실행 계정 | Must |
| FR-5 | 비민감 설정은 `.env`로 두고 `.env.example`을 저장소에 유지한다 | Must |
| FR-6 | 코드·문서·로그 어디에도 실제 비밀값을 적지 않는다 | Must |

**왜 Vault가 아닌가** — 1인~소규모 운영, 단일 서버, 회전 요구 없음.
Vault는 컨테이너와 언실 운영 부담이 이득보다 크다.
**왜 평문 `.env` 단독이 아닌가** — Compose `secrets`는 파일을 `tmpfs`로 마운트해
프로세스 환경에 남지 않는다. 비용 차이가 거의 없는데 노출면이 줄어든다.

## 4. `.gitignore` 기준 — 확정

```gitignore
# 시크릿
secrets/
.env
*.pem
*.key

# 데이터·산출물
db_data/
node_modules/
frontend/dist/
__pycache__/
*.pyc

# 수집 산출물
papers_pdf/          # 논문 PDF 임시 저장 (architecture.md §7.2)

# 에이전트 로그 — agy 프롬프트에 경로·구조가 남는다
plan/agy-log/
```

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-7 | 위 항목을 `.gitignore`에 둔다 | Must |
| FR-8 | 최초 커밋 전에 `git status`로 `secrets/`·`db_data/`가 누락됐는지 확인한다 | Must |

## 5. 인증 관련 시크릿 정책 (PRD-01 연계)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-9 | 비밀번호 해싱은 **Argon2id** — `memory=64MiB, iterations=3, parallelism=4` | Must |
| FR-10 | 비밀번호 최소 10자, 동일 문자 4회 반복 금지, 유출 목록 대조는 하지 않는다(폐쇄망) | Must |
| FR-11 | JWT 서명 키는 `secrets/jwt_secret`(32바이트 이상 랜덤)에서 읽는다 | Must |
| FR-12 | 관리자 초기 비밀번호는 `secrets/admin_initial_password`로 주입하고, **최초 로그인 시 변경을 강제**한다 | Must |
| FR-13 | 실패한 로그인 시도는 계정당 5회/10분으로 제한한다 | Should |

## 6. 로그 마스킹

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-14 | 로그에 비밀번호·토큰·API 키·쿠키 값을 남기지 않는다. 직렬화 전 키 이름 기준으로 마스킹한다 | Must |
| FR-15 | 마스킹 대상 키: `password`, `passwordHash`, `token`, `authorization`, `cookie`, `secret`, `apiKey`, `clientSecret` | Must |
| FR-16 | 이메일은 로그에 남길 때 `a***@example.com` 형태로 부분 마스킹한다 | Should |
| FR-17 | 외부 API 호출 로그에 쿼리스트링의 키 파라미터를 남기지 않는다 | Must |

## 7. 개인정보 — 수집 최소화와 보관

| 항목 | 결정 |
|---|---|
| 회원 수집 항목 | **이메일 + 비밀번호 해시만.** 이름·전화번호·생년월일을 받지 않는다 |
| 구독 키워드 | 회원과 연결해 저장 (기능상 필수) |
| 검색어 로그 | **수집하되 회원 ID와 연결하지 않는다.** 질의어·시각·결과 건수만 |
| 검색어 로그 보관 | **30일 후 자동 삭제** |
| 회원 탈퇴 | 즉시 삭제 (soft delete 후 30일 유예 아님 — 보관할 이유가 없다) |
| 접근 로그 | IP는 저장하지 않는다. 폐쇄망 단일 서버라 추적 필요가 낮다 |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-18 | 회원 테이블에 이메일·비밀번호 해시·역할·생성일 외 개인정보를 두지 않는다 | Must |
| FR-19 | 검색어 로그에 회원 식별자를 기록하지 않는다 | Must |
| FR-20 | 검색어 로그를 30일 주기로 삭제하는 배치를 둔다 | Must |
| FR-21 | 탈퇴 시 회원 행과 구독 키워드를 즉시 삭제한다 | Must |

## 8. 허용 아웃바운드 (architecture.md §1 연계)

완전 폐쇄망이 아니다. 수집 파이프라인이 나가야 하는 대상만 허용한다.

| 대상 | 용도 |
|---|---|
| `export.arxiv.org` | 논문 메타데이터·PDF (PRD-03 FR-21) |
| `api.semanticscholar.org` | 논문 메타데이터 |
| `api.gdeltproject.org` | 국제 뉴스 (PRD-03 §4.1) |
| `openapi.naver.com` | 국내 뉴스 |
| 등록된 RSS 피드 호스트 | PRD-03 §4.1의 매체 목록 |
| SMTP 서버 | 가입 인증 메일 발송 (PRD-01 §5, 2026-09-24 추가) |

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-22 | 위 목록 외 아웃바운드는 기대하지 않는다. 늘어나면 이 문서를 먼저 고친다 | Must |
| FR-23 | **수집된 콘텐츠를 외부로 보내지 않는다** — 번역은 온프레미스 (PRD-03 FR-13) | Must |
| FR-24 | 개발 도구(Antigravity `agy` 등)에 시크릿·`db_data/` 실데이터·수집 콘텐츠를 노출하지 않는다 (`CLAUDE.md`) | Must |

## 9. 회전 정책

**정기 회전을 하지 않는다.** 1인 운영·단일 서버·폐쇄망에 가까운 환경에서
회전 자동화는 이득보다 운영 실수 위험이 크다. 대신:

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-25 | 유출이 의심되면 즉시 교체한다. 교체 절차를 `README`에 적는다 | Must |
| FR-26 | JWT 서명 키 교체 시 기존 세션이 모두 끊긴다는 점을 절차에 명시한다 | Must |

## 10. 수용 기준

- [ ] `git status`에 `secrets/`·`.env`·`db_data/`가 나타나지 않는다
- [ ] 컨테이너에서 `env`를 실행해도 비밀번호·키가 보이지 않는다
- [ ] 잘못된 비밀번호로 6회 로그인하면 차단된다
- [ ] 로그 파일에 `password`·`token` 값이 평문으로 남지 않는다
- [ ] 31일 지난 검색어 로그가 남아 있지 않다
- [ ] 관리자 초기 비밀번호로 로그인하면 변경 화면으로 강제 이동한다

## 11. 미결 사항
