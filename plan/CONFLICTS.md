## 2. 2차 검증에서 새로 발견된 충돌 (N-1 ~ N-4)

C-1~C-9를 해소하면서 새로 드러난 것들이다.

### N-1. 포인트 컬러의 용처가 사라졌다 🟡 → 해소

PRD-04 §5.1이 포인트 컬러를 *"카테고리 태그와 **원문 이동 버튼**에만"* 쓰라고 했는데,
C-4 해소로 **원문 이동 버튼이 폐지**됐다. 동시에 배지·토글·하이라이트 등 색이 필요한
곳이 새로 생겼다.

→ **해소:** `design-system.md` §2.3에서 포인트 팔레트를 재정의.
카테고리 태그는 아예 색을 빼고 글자로 구분한다(NFR-5도 함께 만족).

### N-2. 워커 구성이 문서 간에 어긋났다 🔴 → 해소

`architecture.md` §4와 PRD-03 §5.6이 **"GPU 1장당 워커 1개 × 8"** 이라고 적혀 있었으나,
7B fp16 모델은 가중치만 약 14GB로 **12GB 1장에 들어가지 않는다.**
확정된 모델과 워커 구성이 물리적으로 모순이었다.

→ **해소:** **GPU 2장 × 4워커**로 통일 (PRD-03 §8.1, architecture.md §4).
NUMA 그룹(0~3 / 4~7) 안에서만 짝을 짓는다. 1장 × 8워커는 3B 대안일 때의 구성.

### N-3. 메인 1페이지 전제가 깨졌는데 라우터가 없다 🟡 → 해소

C-1(논문 상세)·C-3(PRD-06) 해소로 화면이 5종으로 늘었는데,
`frontend/package.json`에 라우터가 없고 PRD-04 §6 기술 스택 표에도 빠져 있었다.

→ **해소:** `react-router-dom 6`을 필수로 추가 (architecture.md §6, PRD-04 §6).

### N-4. 보조 텍스트 색이 접근성 기준에 미달 🟡 → 해소

PRD-04 NFR-5가 접근성을 요구하는데, 같은 문서 §5.1이 지정한 보조 텍스트 `#8B95A1`은
흰 배경에서 **대비비 약 2.9:1로 WCAG AA(4.5:1) 미달**이었다.

→ **해소:** `design-system.md` §2.2에서 텍스트 토큰을 AA 통과값으로 재정의.
`#8B95A1`은 비활성·placeholder 전용으로 강등.

## 3. 리스크

### R-1. 전량 번역 부하가 배치 간격을 넘길 수 있다 → **부분 해소, 검증 대기**

수집 상한이 **뉴스 100 / 논문 30 (배치 1회)** 으로 확정돼 계산이 가능해졌다.

| 항목 | 값 |
|---|---|
| 배치당 번역 콜 | 320콜 |
| 4워커 분담 | 워커당 80콜 |
| 배치 간격 | 12시간 |

→ **남은 것: PRD-03 FR-42 벤치마크.** Qwen2.5-7B-Instruct fp16 × GPU 2장에서
워커당 80콜의 실소요를 측정한다. 12시간을 넘기면 3B 대안으로 전환.
**이것이 전체 계획에서 유일하게 남은 미검증 항목이다.**

### R-2. PDF 휴리스틱 섹션 추출의 실패율 → **완화**

폴백 경로가 명시돼 있고(FR-15), 폴백 시에도 다음이 보장된다:

- 화면에는 "초록만 제공" 안내가 나간다 (PRD-04 FR-25, design-system §7)
- 카드에 상태 배지가 붙는다 (PRD-04 FR-20)
- **검색은 `fullTextOriginal`(FR-29)로 별도 확보**되므로, 섹션 추출이 실패해도
  영어 검색 범위는 줄지 않는다 — C-2 해소가 R-2를 함께 완화했다

남는 영향은 "3섹션 번역의 가치"뿐이며, 추출 성공률은 FR-20으로 집계해 개선한다.

### R-3. 다중 소스 중복 제거의 난이도 → **완화**

DOI/arXiv ID 우선 키(§4.2)와 URL 정규화 규칙이 명시됐고,
소스 목록이 §7.1~7.3에서 확정돼 대상이 특정됐다.
구현 난이도는 남지만 **불확실성은 해소**됐다.
