# SPEC-012: 수집 품질 측정

| 항목 | 값 |
|---|---|
| 근거 | PRD-03 §4.5 (수집 품질 검증 체계) |
| 목적 | 6개 축을 **실제로 측정**하고 통과선 미달을 드러낸다 |
| 선행 조건 | **SPEC-004 완료** (수집이 돌아 DB에 데이터가 있어야 한다) |
| 성격 | 게이트 — 여기서 미달하면 다음 단계로 가지 않는다 (FR-70) |

## 1. 왜 필요한가

사용자가 "가장 중요한 것은 수집과 번역 품질"임을 명시했다.
그런데 수집은 **건수만 세고 품질은 재지 않았다.** FR-26(소스별 건수)과
FR-20(섹션 추출 성공률)만 있고 **통과선이 없었다.**

번역 품질은 SPEC-011이 맡는다. **이 명세는 수집 쪽이다.**

## 2. 측정할 6개 축 (PRD-03 §4.5.1)

| # | 축 | 지표 | 통과선 | 측정 방법 |
|---|---|---|---|---|
| 1 | 오병합 | 서로 다른 항목을 합친 건수 | **0건** | 병합 로그 전수 + Claude 검수 |
| 2 | 미탐 중복 | 같은 항목이 2건 이상 남은 비율 | ≤ 3% | 자동 탐지 |
| 3 | 주제 관련성 | 보안 주제인 비율 | ≥ 85% | Claude가 표본 50건 판정 |
| 4 | 섹션 추출 | `full` 비율 / Abstract 이상 확보율 | ≥ 60% / ≥ 95% | 자동 집계 |
| 5 | 요약 확보 | 뉴스 중 요약이 있는 비율 | ≥ 80% | 자동 집계 |
| 6 | 신선도 | `published_at` 7일 이내 비율 | ≥ 90% | 자동 집계 |

## 3. 만들 것

```
tools/ingest_quality.py     측정 본체
  --report                  6개 축 집계 → JSON + MD
  --sample-relevance N      관련성 검수용 표본 N건 추출 (기본 50)
  --duplicates              미탐 중복 후보 목록
  --merges                  병합 이력과 근거
```

### 3.1 자동 측정 (축 2·4·5·6)

| ID | 요구사항 |
|---|---|
| I-1 | `contents` 테이블을 읽어 축 4·5·6을 집계한다. 별도 수집을 하지 마라 |
| I-2 | 축 4 — `section_extract_status` 분포(`full` / `abstract_only` / `failed`) |
| I-3 | 축 5 — `type='news'` 중 `summary_original IS NOT NULL` 비율 |
| I-4 | 축 6 — `published_at`이 수집 시점 기준 7일 이내인 비율. `published_at`이 NULL이면 별도 집계 |
| I-5 | 결과를 `batch_runs.stats`와 같은 형태로 내고, 통과/미달을 **축마다 명시**한다 |

### 3.2 🔴 미탐 중복 탐지 (축 2)

dedup을 통과해 **남아 있는** 중복을 찾는다. 이건 dedup 로직과 **다른 기준**을 써야 한다 —
같은 기준을 쓰면 당연히 0건이 나온다.

| ID | 요구사항 |
|---|---|
| I-6 | 제목 정규화(소문자·공백·구두점 제거) 후 완전 일치 쌍을 찾는다 |
| I-7 | 논문은 제목 정규화 일치 + 저자 첫 번째가 같으면 중복 후보 |
| I-8 | 뉴스는 **같은 매체 안에서만** 제목 일치를 중복으로 본다. 다른 매체의 같은 사건 보도는 중복이 아니다 (PRD-03 C-18) |
| I-9 | 찾은 후보를 **목록으로 낸다.** 자동으로 병합하지 마라 — 판단은 사람이 한다 |

### 3.3 🔴 오병합 검수 (축 1)

| ID | 요구사항 |
|---|---|
| I-10 | SPEC-004의 병합 로그(FR-65)를 읽어 **병합 이력 전수**를 낸다 |
| I-11 | 각 항목에 병합 근거(URL 정규화 일치 / DOI 일치 / arXiv ID 일치)와 **합쳐진 양쪽의 제목·URL**을 함께 낸다 |
| I-12 | 근거가 제목 유사도인 건이 있으면 **즉시 실패로 표시한다** — FR-64 위반이다 |
| I-13 | 판정은 Claude가 한다. 이 스크립트는 **판단하지 말고 재료만 낸다** |

### 3.4 관련성 표본 추출 (축 3)

| ID | 요구사항 |
|---|---|
| I-14 | `--sample-relevance 50` — 수집 항목에서 **무작위 50건**을 뽑아 제목·요약·`matched_keywords`·출처를 낸다 |
| I-15 | 표본은 재현 가능해야 한다 (시드 고정) |
| I-16 | 키워드별 분포를 함께 낸다 — "AI" 키워드가 보안 무관 기사를 얼마나 끌어오는지 보려는 것이다 |
| I-17 | **판정을 자동으로 하지 마라.** Claude가 읽고 판정한다 |

## 4. 출력

`plan/quality/ingest-{YYYYmmdd}.md` — 사람이 읽는 보고서.

**첫 줄에 6개 축의 통과/미달을 한 줄로 요약한다.**

```
축1 오병합 ✅ 0건 | 축2 중복 ✅ 1.2% | 축3 관련성 ⏳ 검수대기
축4 섹션 🔴 41% (기준 60%) | 축5 요약 ✅ 88% | 축6 신선도 ✅ 94%
```

| ID | 요구사항 |
|---|---|
| I-18 | 미달 축은 🔴로, 사람 판정 대기는 ⏳로 표시한다 |
| I-19 | 미달 축에 대해 **가능한 원인 후보**를 적는다 (예: 섹션 추출 미달 → 2단 조판 인식 실패 / 섹션명 변형 미매칭 / Semantic Scholar 경유 PDF 부재) |
| I-20 | 축 3·1용 재료(표본 50건, 병합 이력)를 같은 파일에 붙인다 — Claude가 바로 읽고 채점할 수 있게 |

## 5. 🔴 하드 제약

| 제약 | 내용 |
|---|---|
| 판정 금지 | 이 스크립트는 **재료만 낸다.** 관련성·오병합 판정을 자동화하지 마라 (I-13, I-17) |
| 자동 병합 금지 | 중복 후보를 찾아도 **합치지 마라** (I-9) |
| 수집 금지 | 새로 수집하지 마라. DB에 있는 것만 읽는다 (I-1) |
| 외부 LLM 금지 | 관련성 판정에 외부 API를 쓰지 마라 (PRD-03 FR-13·FR-60) |
| 통과선 임의 변경 | PRD-03 §4.5.1의 수치를 코드에서 바꾸지 마라. 설정으로 읽되 기본값은 그대로 |
| 기준 재사용 금지 | 축 2 탐지에 dedup과 **같은 기준을 쓰지 마라** (§3.2) |

## 6. 검증 방법

- [ ] `python tools/ingest_quality.py --report` 가 6개 축 집계를 낸다
- [ ] 보고서 첫 줄에 축별 통과/미달 요약이 보인다
- [ ] 미달 축에 원인 후보가 적혀 있다
- [ ] `--duplicates` 가 중복 후보 목록을 내고 **자동 병합하지 않는다**
- [ ] 서로 다른 매체의 같은 사건 기사가 중복으로 잡히지 **않는다** (I-8)
- [ ] `--merges` 가 병합 근거와 양쪽 제목·URL을 함께 낸다
- [ ] 병합 근거에 "제목 유사도"가 있으면 실패로 표시된다
- [ ] `--sample-relevance 50` 을 두 번 돌리면 **같은 표본**이 나온다 (I-15)
- [ ] 스크립트가 `contents`에 **쓰지 않는다** (읽기 전용)
- [ ] DB 접속 정보가 코드에 없다 (`shared/config.py` 경유)

## 7. 보고할 것

```
CHANGED: <파일>
SUMMARY: <3줄 이내>
RESULT:  <6개 축의 실측치와 통과/미달>
VERIFY:  <§6 각 항목>
CONCERNS: <없으면 none>
```

**미달 축이 나오면 숨기지 말고 그대로 보고하라.**
이 명세의 목적은 "다 됐다"가 아니라 **무엇이 부족한지 정확히 아는 것**이다.
축 4(섹션 추출)가 50% 미만이면 휴리스틱을 더 손대지 말고 보고하라 (FR-71) —
"3섹션 번역" 결정 자체를 재검토해야 할 신호다.
